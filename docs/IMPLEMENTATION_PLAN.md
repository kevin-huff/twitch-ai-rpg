# Implementation plan

Build the local playable slice with tests first, then verify the live providers and deploy to Railway. The initial gate is four players sharing two Mara conversation beats and a reviewed dice action, with the same history after refresh and server restart.

This plan records implementation status and the remaining acceptance criteria. The local slice passed its combined unit/integration run, typecheck, production browser build, six-context browser rehearsal, and a separate live-provider application rehearsal on October 22, 2026. [CODEX_START_HERE.md](../CODEX_START_HERE.md) contains the current startup and provider configuration instructions. M3 through M5 remain unfinished.

## M3: live model, authoring, and reviewed continuity

The ClewdR adapter is implemented against native messages at `CLEWDR_BASE_URL` plus `/messages`. The local base is `http://10.20.30.79:8484/code/v1`. Mocked tests cover the request, JSON parsing, thinking-metadata discard, nonfinal/refusal responses, unavailable speakers, invented continuity references, private-context filtering, redacted errors, and abort timeouts. It makes no automatic paid retries and assumes no provider-enforced structured output. Real planning and rendering succeeded with `claude-opus-5-5-thinking`, despite that name being absent from the advertised model list. Railway needs a reachable replacement base URL.

Context selection excludes raw secrets, hidden identities, director notes, unrelated NPC records, and offstage transcript narration. Plans and scripts pass schemas and domain checks. The continuity prompt now states the validator's exact fact-matching requirement: only supplied public facts or approved public `fact_add` text can be facts; other new statements, including questions heard this beat, must be claims or beliefs. Persisted job generations prevent late responses from replacing later edits. The live ordinary-conversation rehearsal passed, but multi-beat and mixed-outcome quality review, operational usage/cost reporting, and session budgets remain part of this milestone.

Native scenario and character forms, immutable library versions, strict JSON import/export, and custom two-to-six-seat sessions are implemented. Session creation snapshots exact owned versions and remaps package-local references. Lobby card drafts remain private until approval; boundary changes invalidate readiness. The start command requires approved cards and current acknowledgments, with an audited missing-readiness override. Late arrivals can acknowledge boundaries after start. Library edits cannot change live sessions, and post-start card/boundary edits are refused.

Live director controls create/edit NPC profiles, reveal chosen public facts, and change scenes with an explicit present cast. They require a live or paused session and no active beat. Exact state and NPC revisions prevent stale edits. Each change records a private reason, advances the input window, and cancels pending in-character submissions with an explicit acknowledgement. Existing publications and sourced memories remain intact. Reveal facts and selected physical witnesses share one persisted source event. The private location catalog is retained for new custom sessions and excluded from public projections and provider contexts.

Audited corrections now append a public notice referencing a published beat, with optional existing public-fact replacement, strain adjustment, and public-track adjustment. All changes validate against the original state before atomic mutation. Existing factual NPC memories must each be corrected or explicitly retained as beliefs; uninformed NPCs gain no knowledge. Original publications, resolutions, dice, audio, and counters are preserved. The correction cancels pending in-character input and advances the state revision and input window once. Public views expose only the explicit notice; private audit reasons and before/after records remain private. Older corrections stay visible outside the recent transcript window.

Private active-beat direction reaches both planning and rendering. Before lock, saving invalidates plan/stakes review; after lock, it invalidates the draft/continuity review while preserving accepted input, contracts, resolution, and dice. Saving advances beat revision/generation and cancels running jobs, so late provider responses cannot overwrite the new direction. New beats start empty. Provider context prioritizes recently corrected sourced memories within its existing 20-memory budget and labels historical dialogue as subordinate to current state. Correction notice metadata and private direction confer no NPC knowledge or continuity evidence.

The director's session status panel reports task elapsed time, completed speech clips, readiness, recent failures, and the last saved change. Durable attempt records distinguish provider work from cache reuse; unknown tokens and costs remain unavailable. Coverage starts at the displayed tracking date and excludes standalone field/library/character drafting. Application limits are unlimited at the user's request. Broader live-model quality checks remain delivery work; finite budgets can be added when requested.

Acceptance: NPC-03 through NPC-08, STATE-03 and STATE-05. Rehearse multiple follow-ups and mixed outcomes. A director reviews unanswered questions, player agency, contradictions, accidental disclosures, and distinctive NPC speech. Schema conformance alone cannot establish those qualities.

## M4: ElevenLabs speech and broadcast playback

The ElevenLabs adapter, content/configuration cache keys, authorized asset/manifest routes, and leased audio preparation are implemented. Audio is generated from saved narrator/NPC segments. Before publication, recordings remain private to the owning director; player quotes stay silent. Automated provider tests use mocked speech; browser playback uses synthetic clips. Real synthesis passed with the configured model/voice: a standalone 1.52-second MP3 was validated with `ffprobe`, and the live application produced four speech segments. The current key lacks listing permissions, but synthesis works without adding those permissions.

A separate durable playback coordinator appoints one presenter and pins a ready published manifest for each performance. The director controls start, replay, pause, resume, skip, and stop. Player listening and director monitoring are optional, with local volume. Fresh pages remain silent; explicit listening joins the current offset. An active stage must hold a lease that renews for ten seconds. Lease loss pauses shared playback at the last confirmed position, and recovery requires explicit resume. Application startup preserves valid leases. Playback commands and telemetry use separate receipts and revisions without changing canonical game state.

Active browsers poll every 250 milliseconds and schedule transitions 500 milliseconds ahead. Listeners correct drift above 750 milliseconds. This coordinates ordinary browser playback without claiming exact synchronization between audio devices. The presenter alone advances segments on media completion. The director can prepare and preview a saved draft, then publish its exact recording atomically or choose text only. Private recordings bind to the saved script revision and generation, so edits and regeneration invalidate them. Continuity approval preserves the recording. Public audio routes require a published manifest reference; a cached file alone grants no access. Real browser/OBS/voice-call audio routing still needs rehearsal. The playback panel identifies the voices as AI-generated.

Acceptance: SHOW-01 through SHOW-05. Inject speech failure and confirm text-only publication keeps the fixed resolution. Inspect provider requests and asset manifests for private material. Rehearse Open Broadcaster Software (OBS) Browser Source and the actual voice-call audio routing.
