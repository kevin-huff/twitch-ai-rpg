## Run locally

From the project directory:

```sh
nvm install
nvm use
npm ci
npm run local
```

The pinned runtime is Node.js 24.22.1. The local launcher creates `.env` from `.env.example` if needed, generates a private host token, starts the local database when necessary, builds the browser application, and starts the server. Open `http://localhost:3000` and sign in with `HOST_TOKEN` from `.env`. Keep that token stable to retain access to owned sessions and libraries. The host screen opens the library, creates a rehearsal session, or resumes a saved one.

The launcher uses native PostgreSQL on `127.0.0.1:55432`, with data under `.local/postgres`; PostgreSQL 14 is available on this machine. Set `PG_BIN` when the PostgreSQL binaries are elsewhere. `.env`, database files, and generated audio are local runtime data and are ignored by Git.

`compose.yaml` provides PostgreSQL 17.11 and the application with persistent database/audio volumes. Docker is unavailable in the current environment, so the Docker build and Compose path have not been verified. If you start only the Compose database and run the app on the host, include the matching `POSTGRES_PASSWORD` in both `DATABASE_URL` and `TEST_DATABASE_URL`; the passwordless defaults work with the native local database. The full Compose app already overrides its database URL with the configured password. The application applies the numbered SQL migrations at startup, recording them in `schema_migrations` under a database advisory lock.

For solo testing, open the director workspace, choose **Cast & lobby**, and click **Test as Rook**, **Test as Lark**, **Test as Quill**, or **Test as Pip**. Each link opens an independent player tab in the same browser and leaves real player invitations available. The director and character tabs retain their identities across refresh and navigation. These test seats use the actual session: their submissions become ordinary player input.

Player invites and the stage invite appear when the session is created, and each works once. **Seats & invitation links** in Cast & lobby shows a waiting invite again or reissues it. Invited roles can also share one browser in separate tabs. Player and stage credentials last 12 hours, so a player whose seat lapses needs a reissued link. For OBS, use a stream link rather than the stage invite. A director can open the stage in the host browser and still receives the stage-only projection. Stop an already-running application with Ctrl+C and run `npm run local` to load the AI field drafting buttons and current server routes, then sign in and resume a saved session or create a custom show.

### The stage in OBS

OBS loads the stage from a stream link: `/stream?layout=scene|overlay&audio=present|listen|off#token=…`. The host or a producer makes links in **Cast & lobby** under **Stage & OBS links**: one main show link, plus a personal link for any player, the host or a producer. Players can make their own under **My stream view** in Cast & lobby. A link lasts 90 days, needs no click or sign-in, renews its access in the background and stops within seconds of **Revoke**. The token stays after `#`, so it never reaches the server logs.

The full scene layout draws a fixed 1920×1080 picture. The transparent overlay puts the cast, captions, dice, tracks and the wager on panels around a clear camera area. Neither layout shows operator controls. The latest beat always fits: the full scene shrinks its text to a 24 px floor and then pages through long beats with a "Part N of M" marker, while the overlay shows captions in chunks that follow the narration. Before a roll, viewers see each actor's wager, one actor at a time when several act. A **No check** ruling shows "No roll needed" with its single outcome, and **Blocked** shows its setback text. The previous round's dice step aside while new stakes are up.

Only the main show link can supply broadcast audio, and only inside OBS. Opened in an ordinary tab, it just listens, and **Open preview** opens any link silently. The old stage route, `/sessions/:id/stage`, is now a preview with operator controls below the picture, and its **Present audio** asks before taking the audio away from OBS. The director's status strip says whether the OBS show link or a preview tab holds the audio. The OBS setup steps are in the in-app help under Stage and OBS.

### Producers

The host creates, shows again and revokes producer links under **Producer access** on the host home. A producer opens `/producer#token=…` and presses **Sign in as producer**. The link lasts 30 days and each sign-in 12 hours. `apps/server/src/credentials.ts` reads a producer credential as the host, so producers can do everything the host can except manage producer access, which `isHostOnly` guards. Revoking signs the producer out everywhere at once. Stream links that producer made stay on until someone revokes them. Audit rows record the producer grant behind each change.

### Director, players and invitations

The director page has a sticky show bar with status chips (table status, queue, stage audio, last publish), the current step and **Go to beat**. A step tracker and a sticky action bar keep one gold button on the next step. **Lock and draft** handles an ordinary conversation in one press. **Regenerate script**, and publishing with unapproved continuity updates, both ask first, and a player's pause request shows as a notice. The stakes editor counts characters against what the stage fits (90 for a goal, 110 for an outcome), and the AI planner's instructions ask for the same lengths.

**Seats & invitation links** in Cast & lobby shows a waiting invitation again or reissues it, optionally signing out whoever holds the old link.

### The player seat (October 24)

The seat at `/sessions/:id/play` is now a plain form for players who have never played a tabletop game. From top to bottom it shows the show and scene titles, who you are playing with a fold-out **Who is NAME?** card, one status banner, a short **How this works** guide, **Say something** and **Do something** with one box each, a receipt, **What you sent** with **Change** and **Take it back**, **Ask the director privately**, **Ask for a pause**, and a compact **Hear the story here** control. The story text, wager, dice, traits, strain, facts, cast list and stage directions are gone from the seat, and players follow the story on the stream. The page picks Do something during an action round. A Do something line reaches the server as one text in both `intent` and `approach`, and the director queue shows it once. Each box keeps its own text and input context, and unsent drafts still survive a reload. The player's own stream link moved to **My stream view** in Cast & lobby.

Kevin's cast reads a shared Claude Doc, "The Story Table: Help and FAQ" (https://claude.ai/artifact/BPdSKNPrrbPpnKTC3FAZoo). It mirrors `apps/web/src/help/content.ts`, so change both whenever a player-facing label changes.

`npm run local` serves `apps/web/dist`, and `npm run build` empties and rewrites that folder, so a build while the app runs swaps files under open pages. When port 3000 is in use, run the browser suite with `bash .local/seat-harness/run-e2e.sh <port>` instead. That local-only script builds into its own folder and uses a private port and database.

### Player-written characters and one-prompt AI (October 24)

Players now write their own characters, and the AI can fill a whole card or a whole scenario from one description. Nothing the AI writes is saved or goes live without a person: drafts land in the form unsaved, no generation route writes to the database, and every player card still needs the director's approval before the show can start.

- **Player-written seats.** In Library > Create a custom show, every seat defaults to **Player writes their own character**; saved cards are still choices. Such a seat starts empty. The player writes the card in Cast & lobby (**Write your character**), with **Create the whole card with AI** and the per-box **AI Generate** buttons, and presses **Submit card for approval**. Until then the director's lobby shows **Waiting for this player's card**. If a player can't come, the director opens **Test as Seat N**, writes and submits the card, then approves it.
- **Private character links** (Library > Invite players to build characters) stay for players who want to prepare days ahead: a link lasts 30 days, a seat sign-in 12 hours. The link page has the same whole-card button.
- **Whole card.** `CardGenerator.vue` sits inside `CharacterForm.vue` on the Library character editor, the private link page and the lobby. The routes are `POST /api/authoring/generate-card` (host and producers), `/api/character-builder/generate-card` (link), and `/api/sessions/:sessionId/character/generate-card` plus `generate-field` (seat, only before the show starts). The link and seat routes check access and revision, call the AI outside any transaction, then check again. `card-generation.ts` repairs the reply: traits come from the strongest and weakest trait the AI names, and "Keep what I've already written" copies back filled boxes (the traits are always picked again). Pronouns the description doesn't state come back as a suggestion, and saving, **Submit to director** and **Submit card for approval** stay blocked until someone presses **Keep these pronouns** or edits them.
- **Whole scenario.** `ScenarioGenerator.vue` sits at the top of the scenario editor, with a Small, Medium or Large size. It runs as an in-memory background job (`scenario-jobs.ts`, `scenario-drafts.ts`): `POST /api/authoring/scenario-drafts` answers 202 and the page polls every 2 seconds. Deadlines are 180, 240 and 360 seconds by size, there is one running job per host or producer grant, finished drafts are kept 15 minutes, and a server restart loses them. The page remembers the job in the tab, so Cancel or a reload can pick a running draft back up. ClewdR writes in two passes, the outline and then each character's private details two at a time, and `fit-json-schema.ts` trims over-long replies to the schema before parsing. `scenario-generation.ts` repairs the draft into a native scenario with fresh ids and lists what it changed. The draft loads as a new unsaved scenario, and AI-suggested boundaries block saving until **Keep these boundaries** is pressed or the list is edited.
- **Tests.** The fake provider has deterministic `generateCard` and `generateScenario`, and both browser test servers subclass `FakeAiProvider`. `help-labels.test.ts` checks that every label the help quotes ships in a `.vue` file.
- **Live ClewdR check (October 24).** `.local/live-ai/timing.ts` runs the real routes' code against ClewdR and logs every call to a ledger that refuses more than 28 calls an hour (Kevin allowed about 30). A whole card took 23 seconds. Medium scenarios took 118 and 121 seconds of their 240, and a Large one took 178 of 360 (6 places, 8 characters). The Large outline used 6,550 of 8,192 reply tokens, thinking included. The first Medium run lost 2 of 4 characters' private details to broken JSON in the AI's reply: an unquoted string, and a phrase in double quotes inside a line of dialogue. `packages/providers/src/index.ts` now tells every whole-form prompt to quote with single quotes, retries a broken outline once when at least 45 seconds remain and a broken character once when at least 15 seconds remain (never after an HTTP error or a timeout), and gives the outline 16,000 reply tokens. The rerun kept all four characters, and ClewdR accepted the 16,000 limit.

### Scene pictures, action pictures and portraits (October 24 and 25)

Sogni (https://docs.sogni.ai/api-reference/) now draws a picture for every scene and every action round, portraits for player characters and portraits for non-player characters. Pictures never hold up the show: no command, beat, start or approval waits for one, and a failed picture leaves the screen as it was, without one.

- **Turning it on.** The server reads `SOGNI_KEY` from its environment. Kevin exports it from `~/.secrets.zsh`, so start `npm run local` from a terminal that has it (a new terminal, or `source ~/.secrets.zsh` first). Never put it in `.env`. `IMAGE_PROVIDER` is `sogni` or `off`, and when unset it is `sogni` if the key is set. `SOGNI_IMAGE_MODEL` defaults to `krea-2-turbo`. `SOGNI_HOURLY_LIMIT` is optional: unset means no hourly limit, and a whole number from 1 to 1000 sets one. The startup log prints `Pictures: on (Sogni, krea-2-turbo, safe-content filter off).` or `Pictures: off.` With pictures off, screens show no picture areas and the picture buttons say "Pictures are off on this server". The next start applies migrations `011_images.sql` (the `images` table and its indexes), `012_action_pictures.sql` (two nullable columns, two checks and an index for action pictures) and `013_picture_settings.sql` (below); none changes existing data.
- **Scene pictures.** The server starts one when the show goes live and one for every scene change, and each goes straight to the stream. The full-scene layout first fills the frame with the picture and the show and scene titles for 4 seconds, then shrinks it into a 464×265 panel at the top of the right rail. While a picture shows, the rail's tracks switch to one-line meters so the public facts stay visible. The transparent overlay puts a 336×192 copy in a corner, and seats show a small one in their heading. The director's **Scene picture** panel, first in the right column, has **Draw the place** (once **New picture**), **Draw the last beat**, **Hide picture** and **Show picture**. Hide works while a picture is being made or showing, a round's picture waiting for publish included, so a picture can stay off the stream before its reveal; a scene whose only picture failed has nothing to hide. Show works on any hidden scene, and a hidden scene stays hidden through either draw button.
- **Action pictures.** Every action round whose script has narration gets its own picture, started as soon as the script is drafted (the AI render, or a director's edit that changes the narration). Since the October 25 picture-controls build it is drawn like a picture of a beat (below): from the round's public text and its people's portraits. It is a `scene` row tagged with its round (`beat_id`) and held (`released_at` empty) until the round is published. The director's panel shows it being made, ready with a small preview, or failed with the reason when it is the account, the key or a refusal to draw it; no other screen or image request can see it before publish. Publishing releases the round's newest picture, which then gets the full 4-second reveal, or gets it when it finishes if it is still being made. An aborted round's picture never shows. The stream shows the newest moment: a picture without a round counts from when it was asked for and a round's picture from when the round was published, so a picture that finishes late never replaces a newer one, and publishing a round that has its own picture stops older pictures still being made. Conversation rounds keep the scene picture.
- **Portraits.** **Create portrait** sits in the character form on all three character screens: the Library editor, the private character link and **Write your character** in Cast & lobby. A new portrait lands in the form unsaved, with **Use this portrait** and **Try again**. It travels with the card through saving, **Submit to director** and **Submit card for approval**, and the director sees it when approving. Non-player characters get portraits by themselves when an AI-written scenario loads and when the director adds a character during the show. The Library page makes a draft's portraits three at a time and holds **Save scenario version** until the open scenario's portraits finish. Each character also has **Create portrait** and **Remove portrait**, the scenario editor has **Create portraits for everyone**, and an ended show turns the director's portrait buttons off. Portraits replace the initials on the stage's party cards and the overlay's cast chips, and appear beside speaker names, on the cast list and in the director's cast panel. The stage refits its story text when a portrait appears, and a picture that failed to load is tried again when the snapshot changes it.
- **Picture style.** Every scenario has a **Picture style** of up to 300 characters; blank means "Painterly digital illustration, rich color, cinematic lighting". The whole-scenario AI fills it in, sessions carry it, and every picture in that show uses it. It reaches Sogni exactly as written.
- **What Sogni sees.** `picture-prompts.ts` writes every prompt from public details: the scene title and description, the place's name (never the server's "Current location" or "Other location N" stand-ins), a character's appearance, public role or specialty and pronouns, and the picture style. Character names and aliases are removed from the scene and character text, together with a title abbreviation in front ("Mr. Vale", "Capt. Vale"). Everyday words inside names ("The", "Old", "Grey", "Capt") stay when they appear alone, so "Grey studies the map" keeps "Grey". Secrets, hidden identities, director notes and private location notes never reach Sogni. A words-only request carries a negative prompt against text, watermarks and nudity (a portrait-referenced one cannot; its closing sentences ask for the same), and Sogni's safe-content filter is off unless `SOGNI_SAFE_FILTER=on`. Non-player characters have no pronouns field, so the whole-scenario AI now opens each appearance with apparent age and gender, the starter characters do too, and the help asks directors to do the same.
- **Storage and limits.** Picture files sit in `images/` under the asset folder, named by their SHA-256 hash, and routes that check who may see each one serve them. The server makes at most 10 pictures at once, Sogni's own per-account limit, and others wait for a turn with no deadline for as long as they are still wanted (4 at once and a one-minute wait before October 25). On October 25 Kevin asked why pictures had caps at all, so the per-show, hourly and per-character caps are gone; only the optional `SOGNI_HOURLY_LIMIT` remains (`image-settings.ts` parses it). A restart, or a database error just after a picture is reserved, marks a picture still being made as failed instead of leaving it stuck.
- **Code.** Contracts are in `packages/contracts/src/images.ts`, and `SogniImageProvider` is in `packages/providers/src/index.ts`. The server adds `images.ts` (the image service), `image-jobs.ts`, `image-slots.ts`, `image-files.ts`, `picture-limits.ts`, `picture-prompts.ts`, `picture-views.ts`, `picture-routes.ts`, `portrait-routes.ts` and `fake-images.ts`. The web adds `ScenePicturePanel.vue`, `NpcPortraitControls.vue`, `PictureAvatar.vue`, `PortraitGenerator.vue` and `pictures.ts`. Tests use `FakeImageProvider`, which returns a small deterministic PNG; both browser test servers use it with a 1-second delay unless `BROWSER_PICTURES=off`. `tests/browser/pictures.spec.ts` covers the reveal, hide and show, the rail layout, the overlay corner and a held action picture, and `portraits.spec.ts` follows a player's portrait from creation through approval to the stream.
- **Live Sogni check (October 24 and 25).** `.local/live-images/smoke.ts` runs the real server code against Sogni on a throwaway database: a scene picture, a live non-player portrait and a library card portrait, stopping after 4 pictures. Its first run failed all three. Sogni labels its JPEG files `image/png`, and the adapter refused the mismatch, which every test had missed because they all use fakes. The adapter now lets the file's own bytes decide its type, and a rerun made all three in 28, 15 and 8 seconds. One earlier picture took 81 seconds, so the adapter waited up to 150 seconds; since beat pictures upload portraits first, it waits 300. A final run on the finished code made all three in 14, 19 and 11 seconds, and the starter bartender, drawn as a young man before her appearance mentioned age and gender, came out as a woman in her forties. Kevin's account was on Sogni's Unlimited plan trial, and its 425 Spark balance did not change over the first 13 test pictures. On October 25 `.local/live-images/action.ts` ran one action round with real ClewdR planning and narration (12 to 17 seconds per call) and real Sogni, twice: the round's picture was ready 12 and 24 seconds after the draft, the stage could not fetch it before publish, and it became the stage picture at publish.
- **How it was built.** A 40-ticket sprint built the feature from a reviewed design, then three fix rounds of 14, 12 and 3 tickets fixed what the final reviewers and the live runs found, and the main agent closed four small leftovers. On October 25 a 15-ticket sprint added action pictures and removed the caps, and two fix rounds of 6 and 5 tickets settled the picture order and the failure messages. Each round ended with two or three independent final reviews.

### Picture settings and pictures of a beat (October 25)

Kevin asked for three things: a way to pick each show's art style and picture model, a button that draws the latest beat with its characters in it, and Sogni's safe-content filter off. All three shipped. Pictures of a beat and of action rounds now draw everyone in them, and people with portraits come out looking like their portraits.

- **Picture settings.** The **Scene picture** panel has a **Picture settings** fold-out, closed by default. It holds **Art style** (up to 300 characters, eight quick picks and **AI Generate**), **Picture model** (a dropdown with a one-line note per model) and **Save picture settings**. Saving writes `sessions.picture_settings` (`{style, model}`) and records a `picture.settings_saved` event, and it is refused once the show has ended. A picture uses the saved style, else the scenario's `pictureStyle`, else the default. It uses the saved model while it is still on the list, else `SOGNI_IMAGE_MODEL`, else `krea-2-turbo` (`picture-settings.ts`). A save applies to pictures started after it. The Library scenario editor has a **Picture model** choice (`scenario.pictureModel`) that new shows copy, and Library portraits of non-player characters use it.
- **The models** (`PICTURE_MODELS` in `packages/contracts/src/images.ts`): Krea 2 Turbo (the default), FLUX 3 Klein, Z-Image Turbo, Qwen Image 2512 Lightning, Chroma1-HD, DreamShaper XL, Animagine XL 4.0 and CyberRealistic XL. Each drew a live picture on October 25, and each dropdown note says what it did. Real Dream XL was tried and dropped because CyberRealistic XL matched the same style better.
- **The two buttons.** **New picture** is now **Draw the place**. **Draw the last beat** (`POST /api/sessions/:sessionId/beat-picture`, answering 202 with `{imageId}`) draws the newest beat published in the current scene. `lastBeatInScene` finds it from the `change_scene` and `beat.published` audit events. Until there is one, the button is greyed out and the panel says "No beat has been published in this scene yet." Pressing either button while a picture of this scene is on its way to the stream starts over. Those rows are cancelled, and their calls stop once the transaction commits. A round's held picture is never touched. While a beat picture is being made, the panel says "Drawing the last beat…" (`ScenePictureStatus.drawing`).
- **How a picture of a beat is drawn.** `picture-cast.ts` lists the beat's people from public fields only: speakers, contract actors, helpers and anyone addressed. Non-player characters count only while present in the scene. The first 10 with a ready portrait get a number, because FLUX 3 Klein takes at most 10 reference images. Everyone else is described in words, so nobody is left out. The job (`prepareMoment` in `image-jobs.ts`) uploads those portraits through Sogni's upload links (`prepareReferences`: an upload link, a PUT, then a download link). Each step gets one retry, only https is accepted, the key never goes to the storage hosts, and the signed links live only in memory. People whose upload failed lose their number. The story AI (`describePicture`, 45 seconds) then writes one paragraph about a single frozen moment: no names, no lettering, everyone clothed, and portrait people as "the person from image N". The server takes names out again (`withoutNames` cleans the description, never the style), tidies the text and cuts it at a sentence end to fit. An empty reply, an error or a timeout falls back to a description the server writes from the beat. The prompt is the style, the description and a closing that is never cut: "Keep each person's face, hair, build and clothing as in their reference image. Everyone fully clothed. No text, no letters." With at least one portrait it goes to FLUX 3 Klein as an `edit_image` step with `media_references`. With none, the show's model draws it as `generate_image`. The final prompt and model are saved on the row before the picture waits for a turn.
- **Action rounds** are drawn the same way and stay held until publish, as before.
- **Prompt limits.** Sogni refuses a FLUX 3 Klein prompt over 6,000 characters. The step fails about a second after it starts, with no charge. The model drew a detail from the last sentence of a 5,944-character prompt, so pictures drawn from portraits may use all 6,000 (`MOMENT_PROMPT_MAX`). Pictures drawn from words alone keep 2,000 (`PICTURE_PROMPT_MAX`), the length the app has always sent: Sogni's model catalog lists no limit for Krea 2 Turbo, Z-Image Turbo or Qwen, and the XL models read only about the first 77 tokens. Both live beat prompts ran past 2,000 (2,281 and 2,526 characters).
- **The safe-content filter.** `SOGNI_SAFE_FILTER=on` turns it on. Unset or `off` leaves it off, and any other value stops the server at startup. The startup line names the setting: `Pictures: on (Sogni, krea-2-turbo, safe-content filter off).`
- **Waiting.** Up to 10 pictures run at once, Sogni's own per-account limit, and the rest wait with no deadline while they are still wanted. A picture has 300 seconds at Sogni, and its uploads get 300 seconds of their own.
- **Migration 013** (`013_picture_settings.sql`) adds `sessions.picture_settings` and `images.moment` (the beat's public moment, allowed only on a show's scene rows). It also drops the 2,000-character prompt check from 011.
- **Code.** Server: `picture-settings.ts`, `picture-cast.ts`, the moment half of `picture-prompts.ts` (the two closings, `descriptionBudget`, `momentPrompt`, `cleanDescription`, `fallbackDescription`), `prepareMoment` in `image-jobs.ts`, `reserveBeatPicture` and `startOver` in `images.ts`, `picture-routes.ts` and `picture-views.ts`. Providers: `SogniImageProvider.prepareReferences`, its `edit_image` path and `ClewdrAiProvider.describePicture`. Web: `PictureSettings.vue`, `ScenePicturePanel.vue`, `Library.vue` and `api.ts`. `FakeImageProvider` records models, references and uploads, and `FakeAiProvider.describePicture` returns `FAKE_PICTURE_DESCRIPTION`. Only a story AI passed to `buildApp` describes pictures, so a fake-AI server with a real Sogni key uses the server's own description instead of the fake's one sentence. New browser tests: `beat-pictures.spec.ts` and `action-portraits.spec.ts`.
- **Live checks (October 25).** Free estimates priced all nine candidate models at 1 unit a picture. Seven place pictures, one for each model new to the list, took 11 to 54 seconds. Z-Image Turbo, Qwen and Chroma followed the scene and the style closely. The XL models got the style right but put an underground market outdoors. Then a run through the real server code (`describePicture` on ClewdR, Sogni drawing, a throwaway database) drew an action round and a Draw the last beat picture of the same moment, each with 2 portraits plus 4 people from words. The story AI took 11.5 to 11.8 seconds per description. Sogni took 107 seconds for the first picture and 12 for the second. Likeness was strong, the prompts held no names and the pictures no lettering, and the round's picture stayed off the stream until publish. Spend for the day: 13 Sogni starts, 11 pictures drawn, and 4 ClewdR calls for the final run.
- **How it was built.** A 30-ticket sprint built it from an approved design, and its three final reviewers asked for one fix (tests that pinned the 2,000 prompt limit). The main agent then set the prompt limits, settled the model list, fixed the fold-out's save state and the help wording, and ran the live checks. Type checking is clean, and 1,695 unit tests, 799 database tests and all 34 browser tests pass.
- **Known limits.** Pictures are ranked by database timestamps, and during the final review this WSL2 machine's clock jumped backwards by up to 2.5 seconds several times a minute. Two pictures made within about 2 seconds of each other can therefore swap places, for example a Draw the place pressed just after publishing a round whose picture is ready. Ranking by a database sequence would fix it. A portrait request waits for a turn with no deadline, even after its browser gives up. If a middle portrait upload fails, the later portraits are renumbered in the prompt while their upload names keep the old position. ### Show gallery (October 26)

### Known limits

With five or six players acting at once, the full scene can page story text one row at a time, and the overlay's dice labels can run into each other. The overlay's cast chips cut long names. Producers cannot pick another producer when making a personal link, because only the host can list producers. Each listen-only stream view polls playback four times a second. The browser tests render with Linux fonts, while OBS on Windows uses Georgia and Segoe UI, so a dry run on the streaming machine is still needed.

The seat cannot tell a line written while the last beat was locked from an unpicked line carried over from that beat, because the server stores both with no beat and the same epoch. Its banner counts a no-beat line written for this turn, or left unpicked by the last one, as waiting only when it fits the open turn: talk in a conversation, an action in an action round. A line left unpicked for two turns stops holding the banner, though it stays in the director's queue. If a player presses Send while the "story moved on" notice shows, the server's refusal still reads "The input window changed. Review your input before submitting again." **What you sent** lists every line still in play, plus only the newest finished line and the newest private note, so when a scene change cancels several lines at once, only the newest stays listed.

The AI generators have had four live runs (above), too few to know their failure rate; watch for 'did not fit the form' and for characters that come back with only public details. The live narration prompts (plan and render) did not get the single-quote rule. Scenario drafts live in memory, so a restart loses a draft in progress. A player who has saved AI-suggested pronouns on a private link and reloads can submit without pressing Keep these pronouns (the pronouns stay visible in the form). Lobby and link AI requests have no per-person rate limit, and they share the ClewdR account with live narration, though lobby AI stops once the show starts.

Pictures follow only what the text says: the picture model sees a character's Appearance and Role (plus pronouns for player characters), so an appearance without age and gender can come out either way. Scene pictures never name characters, so people in them will not match the portraits. A name that is also an everyday word, such as Grey, reaches Sogni when it appears alone, and the picture style goes out as written. An AI draft's automatic portraits are made by the open Library page, so closing it early leaves the rest without one until someone presses **Create portraits for everyone**. Picture files are never deleted. The adapter downloads Sogni's signed link from whatever https host Sogni names (media.sogni.ai so far), without the key. Sogni's own account limits, 10 running pictures and 300 starts an hour, still apply. Whether pictures cost anything after the Sogni trial depends on Kevin's plan and is unmeasured. If a round is published without a picture of its own (it failed, or the script had no narration), older pictures still being made are not stopped, so one that finishes late replaces the stream picture after that round. If a round's picture fails after its publish stopped an older one, the stream keeps an older picture or none. A restart while a round's picture is held cancels it, so that round publishes without one.
